# Accepted design decisions 001–013

This document records the design intent established through interactive product decisions. These are architectural commitments, not proof of implementation.

## 001: Maximum Metro (D)
One coherent Metro language across launcher, first-party apps, lockscreen and system surfaces: strong typography, meaningful live tiles, panorama/pivot navigation, iconography, accessible motion and user-controlled themes.

## 002: Android-native first (B)
Start with a Kotlin/Jetpack Compose launcher and portable applications on existing Android. Keep privileged OS integration behind explicit interfaces for eventual AOSP. No claim that a launcher can replace stock SystemUI or Android's system navigation.

## 003: Metro Ultimate (D)
Unify design inspiration from Windows Phone 7 through Windows 10 Mobile: configurable tile sizes and grids, animations, interactive tiles within sandboxed contracts, and consistent backgrounds and accent colors. Do not rely on proprietary Microsoft assets.

## 004: Full AOSP distribution (E)
Target a signed, updateable AOSP-derived OS integrating SystemUI, settings, lockscreen, launcher and shared services. Maintain SELinux, verified boot where hardware supports it, secure app sandboxing, and rollback-aware updates. No arbitrary executable tile code.

## 005: Pixel-first verification (B)
Prototype on emulator/Cuttlefish before any physical flashing. Qualify a specifically supported, unlockable Pixel by verified AOSP device tree, vendor image, radio, camera, security patching and recovery behavior. Ownership of a Pixel 10a does not establish ROM compatibility.

## 006: Fully integrated first-party suite (E)
ZeroStart, ZeroPhone, ZeroMessages, ZeroPeople, ZeroCamera, ZeroGallery, ZeroClock, ZeroCalc, ZeroFiles, ZeroPower, ZeroSettings and ZeroHub share design tokens and bounded service interfaces. Distinguish portable Android components from privileged AOSP-only features.

## 007: Compatibility editions (E)
Pure: Google-free, with honest compatibility limits. Compatible: mainstream compatibility; GMS only when lawfully licensed/certified. Developer: experimental instrumentation without default security bypass. Distinct CI, signing and support policies.

## 008: Power profiles (B)
Balanced, Performance, Battery Saver and Custom through supported Android/vendor controls. No universal promise of thermal/governor overrides. Profile state must be explainable, measurable and reversible.

## 009: Camera-first platform (D)
Pro controls, DNG/RAW, video, histograms, focus peaking and modular imaging pipeline, gated on Camera2/HAL and hardware capabilities. Preserve EXIF and provenance. Future imaging hardware is research, not supported functionality.

## 010: Federated communications (C)
ZeroMessages unifies supported SMS/MMS, RCS where authorized APIs permit, Matrix and optional sanctioned bridges. Label transport and E2EE accurately; never silently downgrade. Contact identity linking is user-confirmed. No assumption of unrestricted access to closed messaging networks.

## 011: Contextual People Hub (D)
ZeroPeople connects favorites, contacts, communications, share sheet, notifications, launcher and local search. Suggestion ranking must be transparent, editable and on-device where possible. Never automatically classify relationship quality. No general third-party People API was accepted.

## 012: ZeroConnections platform (D)
Private digital black book, mutually established connection identities, E2EE shared spaces, directionally consented location sharing, contextual reminders and reliable offline/stale states. Sender controls sharing and recipient controls receipt independently. Detailed design: [ZeroConnections](../connections/zeroconnections.md).

## 013: Connection-first three-button navigation (C)
Persistent **Back / Start / Search** for ordinary use. Back respects Android navigation and overlay behavior. Start returns to Metro Start; long-press Start opens recent tasks. Search opens permission-aware ZeroSearch; long-press Search invokes current-context search where supported. A visible People Hub entry, contact-aware search, shared-plan shortcuts and communication actions make connection a first-class OS workflow. Reserve long-press Back. Accessibility alternatives, immersive exceptions and Android lifecycle semantics required. On stock Android this is a launcher-level approximation; full control requires AOSP SystemUI.

## Core principle ZC-CORE-001
Technology shall reduce friction in initiating human connection while protecting the right to decline, disengage, remain unavailable, or share nothing. Connection-first does not require making unrelated tools social.

## Acceptance boundary
ADR-014 remains undecided. ZeroPresence, Social Availability, ZeroReflections and ZeroMemories are proposals attached to ADR-012, not independent accepted architecture decisions.
